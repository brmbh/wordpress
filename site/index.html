What's in the box

A foundation that earned its parts.

ACF block factory

Drop a four-file folder into my-acf-blocks/ and it self-registers. WordPress-standard block.json — AEO-ready.

Bootstrap 5 ↔ Gutenberg

One variable layer bridges Bootstrap's grid and utilities to the block editor. Editors never type a class.

Agent skills built in

Canonical AGENTS/ skills, with auto-generated wrappers for Claude, Cursor & Windsurf.

Figma token pipeline

Pull design tokens from Figma Variables straight into _tokens.scss. Design system stays in sync.

Deploy & DB suite

Rsync deploys and database pull/push between environments — wrapped behind clean, guarded commands.

Code-first CLI

One CLI for the whole lifecycle. Every command speaks human and machine — pass --json for agents.

Built for agents

Every command speaks human and machine.

Pass --json and any command returns a clean envelope instead of prose. Each one declares a level that tells an agent exactly how to use the result. Pick one:

Raw data → the agent interprets

The tool reports facts and stays out of the decision. The agent reads the data and decides what to do next. Good when the situation is ambiguous.

brmbh dev --once --json
$ brmbh dev --once --json { "ok": true, "message": "Build complete", "script": "build", "themeDir": "wp-content/themes/my-site" }

A class → the agent branches

The tool does the classifying and hands back a single field to switch on. No re-deriving health from raw output — just branch on class. This is doctor.

brmbh doctor --json
$ brmbh doctor --json { "ok": true, "message": "Environment: ready", "class": "ready", "checks": [ { "name": "node", "status": "ok" }, { "name": "build", "status": "ok" }, { "name": "acf-pro", "status": "ok" } ] }

A next procedure → the agent executes

The tool returns a literal, ordered list of follow-up steps. The agent runs them verbatim — no guessing. This is create and add.

brmbh add block hero --json
$ brmbh add block hero --json { "ok": true, "message": "Added block \"Hero\"", "slug": "hero", "next": [ "Define the ACF fields in fields.php", "Render them with Bootstrap utilities + tokens", "Rebuild styles: brmbh dev --once" ] }
Why this is powerful

Your agent doesn't just scaffold. It works the whole stack.

Server & client, both

The theme is vanilla PHP with a real JS build — no Blade, no black box. So an agent writes both halves: server-side PHP (ACF blocks, custom post types, render templates) and client-side JavaScript (Bootstrap behaviour, GSAP scroll animations, interactions). One agent, full stack.

  • server ACF blocks · CPTs · template.php · hooks
  • client GSAP · Bootstrap JS · interactions · the build

wp-cli as a backend MCP

WordPress ships wp-cli — a complete, scriptable interface to the backend. brmbh's deterministic tools wrap it, so an agent can operate the CMS like an MCP tool surface: create posts and pages, manage plugins, run search-replace, query the database, sync environments.

  • read query posts · options · plugin & version drift
  • write create content · activate plugins · DB pull/push
Human in the loop

The agent builds fast. You never lose the wheel.

It's plain PHP and the WordPress patterns you already know — ACF, Gutenberg, block.json, the loop. Little abstraction, nothing proprietary to learn. Every file the agent writes is one you can read, edit, and own. Jump in at any line.

Plain PHP

No black box

No Blade, no compile step to read a template. Open template.php and it's just PHP and HTML.

WordPress-standard

Grounded in real WP

Standard block.json, ACF, the loop and hooks — the conventions WordPress already ships, not framework-specific ones to learn.

Yours to edit

Take over anytime

Every generated file is readable and hand-editable. Step in, change a line, hand it back. The agent accelerates you — it doesn't replace you.
